# 実装計画(IMPLEMENTATION_PLAN)

フェーズは順番に実装する。各フェーズの完了条件をすべて満たし、運営者の動作確認を得てから次へ進む。
フェーズを跨いだ先行実装をしない。

## フェーズ0: 基盤準備

- 目的: 開発を始められる状態を作る
- 前提: Supabase / Vercel / Resend / GitHub のアカウント(運営者が作成、手順は都度案内)
- タスク: Next.js+TypeScript+Tailwindプロジェクト作成 / GitHubリポジトリ(private) / Supabaseプロジェクト作成・接続 / .env.example整備 / ESLint・Prettier / Vitest・Playwright導入 / Sentry接続 / 基本レイアウト(ヘッダー・フッター・フッターに全空連非公式注記)
- テスト: ローカルで起動しトップの雛形が表示される
- 完了条件: ローカル開発環境が動き、mainへのpushでVercelプレビューが生成される

## フェーズ2: 管理者機能(道場データ管理)

## MVP受入れ基準(全体)

1. スマホで「県→市→道場→体験申込み」が3分以内に完了できる
2. 道場運営者が管理権限を得て、自道場の情報を自力で更新できる
3. 申込みが道場へメール通知され、件数が集計される
4. 電話タップ数が記録・表示される
5. 掲載0件地域の空ページが検索エンジンに露出しない
6. 個人情報が180日で自動匿名化される
7. 運営者以外の管理者アカウントが存在し、OPERATIONS.mdだけで基本運用ができる

## 想定リスクと対策

| リスク | 対策 |
|---|---|
| 道場データが集まらない | 道場主自身の無料登録が原則。初期は運営者の声かけ+/for-dojosページで募集。同意を得た道場のみCSVで代理登録可 |
| なりすまし・虚偽登録 | claim承認時の確認メモ・監査ログ・即時非公開化・通報窓口 |
| 全空連からの指摘 | 非公式である旨の常時表示・ロゴ不使用・名称は事実説明の範囲。指摘があれば/contactから受け、表示を修正 |
| 無料枠超過 | Vercel/Supabase/Resendの使用量をOPERATIONS.mdの月次確認に含める。超過時は有料プラン(月計7,000円前後)へ |
| 運営者の長期不在 | 複数管理者・自動公開への切替不要な設計(owner編集は即時反映)・匿名化等の自動処理・OPERATIONS.md |
| メール不達 | ドメイン認証・Sentry通知・owner画面でも申込みを確認可能(メール依存にしない) |
